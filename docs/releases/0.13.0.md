# Lionscope 0.13.0

Release preparation notes. Source integration uses reviewed PRs into `main`; the maintainer will publish npm
and MCP metadata separately after the merge handoff. Set the release date when publishing.

## Highlights

- **Live permissions:** all four debugging permissions start enabled. Change them from dashboard Permissions
  or `lionscope permissions`, without restarting; choices are saved locally per server port.
- **Storage Inspector:** browse SharedPreferences and registered Room databases, edit typed row drafts including
  primary keys, and inspect confirmed write outcomes. Read/write permissions start enabled and can be disabled live.
- **Database Query console:** run a validated SELECT/WITH or INSERT/UPDATE/DELETE statement against the app's
  registered Room connection. SQL mutations require write consent and report affected rows; they have no
  row-editor compare-and-set or undo contract.
- **SQL agent tools:** `query_storage_sql` and `execute_storage_sql` expose the same SQL execution over MCP and
  CLI, with separate read/write permissions and original app/link targets. Storage writes are not replayed on
  MCP reconnect.
- **Background CLI:** `lionscope` starts a managed local server and returns the terminal. Use `lionscope status`,
  `lionscope logs` and `lionscope stop` to manage it.
- **Network originals and Copy cURL:** inspect original captured auth headers, URL values, body text and failure
  messages on protocol 14. Copy complete requests as POSIX-shell cURL commands; incomplete captures explain why
  copying is unavailable.
- **Dashboard:** five workspaces, clearer Storage source hierarchy, compact editors, responsive metric labels,
  and independent Storage/Network mirror choices that start shown. Chromium regressions enforce layout contracts.

## Upgrade notes

Debugging permissions now start enabled: agent device control, Network bodies for agents, Storage read and
Storage write. Saved choices override those defaults. Disable any from dashboard Permissions or CLI with the
matching `--disable-*` flag. Choices are saved locally per server port and apply without restarting. Clients
cannot override a disabled server permission. Already running operations may finish.

```sh
lionscope                                      # background server; fresh installation has all permissions on
lionscope permissions --disable-storage-write  # keep Storage read-only without restarting
lionscope permissions --allow-storage-write    # enable Storage read and write again
```

The same command supports `--disable-device-control`, `--disable-network-bodies` and `--disable-storage-read`.
Disabling Storage read also disables writes. Existing `--allow-*` flags remain supported; MCP client flags
provide client restrictions and do not override the server's saved choices. See
[permission configuration](../configuration.md#permissions).

`lionscope` now runs in the background by default. Scripts that expect an attached process should use
`lionscope --foreground`. Development scripts and MCP stdio retain their attached lifecycle.

After upgrading, check `lionscope status`: starting the new CLI reuses an existing listener rather than replacing
it. Stop an owned older background server with `lionscope stop`, then start 0.13.0. An externally started attached
server must be closed from its owning terminal. Updating installed files alone does not upgrade a running server.

Network on negotiated device protocol 14 preserves credentials. Headers and URLs remain readable by agents;
body text follows the enabled-by-default Network bodies permission and client restrictions. Copying a request explicitly places its credentials on the
clipboard. Legacy links retain redaction. Logcat, crash and saved-state redaction policies are separate.

Storage protocol 12 returns original values, including credentials, and supports primary-key edits. Older
links retain their restrictions. The Query console and SQL agent tools require protocol 13. Storage read/write starts enabled on a fresh installation and still needs a proven active SDK link.
Use dashboard Permissions or `lionscope permissions --disable-storage-write` to restrict it without restarting.
MCP stdio starts with all client permissions enabled and follows server restrictions; reconnect the client after upgrading to discover the
new tools. CLI examples are in [Storage](../features/storage.md#sql-through-mcp-and-cli).

Update both the CLI and the app's debug SDK to **0.13.0** for the complete feature set. Apps calling Lionscope
APIs also need the matching release no-op artifact. Dashboard/device protocol numbers are compatibility
versions and remain 14; they are not package versions.

## Scope and evidence

This candidate combines PR #34 (Storage), #36 (CLI), #37 (Network), SQL agent tools and the local runtime
permissions follow-up.

Runtime permissions have synthetic transport, installed-package and browser coverage plus JVM queued-revocation

are a limited local baseline, not a general overhead guarantee.
